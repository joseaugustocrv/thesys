# Operation and evolution

Software engineering continues after release. Operation provides real-world evidence that can generate new engineering work.

## The post-release loop

```text
Release
  ↓
Deploy
  ↓
Operate
  ↓
Observe
  ↓
Learn
  ↓
Change
  ↓
Revalidate
  ↓
Implement
  ↓
Verify
  ↺
```

## Maintenance

Maintenance can include corrective work, adaptive changes, performance improvements, security remediation, dependency updates, refactoring, technical-debt reduction and operational improvements.

## Incidents and problems

An incident concerns an observed operational problem. Problem analysis seeks to understand causes and contributing conditions so corrective action can address more than the immediate symptom when appropriate.

## Evolution

New requirements, changing constraints and operational learning should enter the same controlled engineering model used for initial development. This preserves traceability instead of creating a second, undocumented lifecycle after release.

## Retirement

A system's lifecycle eventually ends deliberately. Retirement may include migration of users or data, dependency removal, decommissioning, archival or disposal, security closure, operational documentation and evidence of completion.
