# Design principles

## Intent before implementation

Engineering starts by making the desired outcome explicit. Implementation should be a consequence of understood intent rather than the place where intent is discovered accidentally.

## Authority is explicit

A draft, suggestion or generated result is not automatically an engineering decision. Authority is established through the project's defined governance.

## Traceability over paperwork

Documentation exists to preserve engineering meaning. Thesys favors relationships between important decisions and evidence over documents that exist only because a process requires them.

## Change propagates from sources

Derived artifacts should not silently diverge from the decisions that justify them. Significant changes trigger impact analysis and revalidation.

## Evidence over assertion

Claims such as complete, secure or ready should be supported by appropriate engineering activities and observable evidence.

## Risk-proportional rigor

The methodology should be strict where failure matters and lightweight where consequences are small. Rigor is a function of context, not document volume.

## Human accountability with AI acceleration

AI can increase engineering throughput, analysis and implementation capacity. It does not remove human responsibility for consequential decisions.

## Recursive scalability

The same engineering model should work at system, domain, module, service and feature levels. Large systems should be decomposable without losing traceability to higher-level intent.

## Tool independence

The methodology should remain meaningful when implementation tools, AI providers, programming languages or delivery platforms change.
